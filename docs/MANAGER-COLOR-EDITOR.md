# Manager color editor

The floor opens on the compact, readable schedule. **Gerente** unlocks the manager-only editor; staff can see saved assignments in Horario, Tareas, and Más ocupado, but not the paint palette or classic Tablero controls. The top row provides board, date, view, manager, Más, and Ocultar. Mostrar restores a hidden toolbar. The training traffic panel and its background simulator tick are dormant.

In Pintar posiciones, a manager picks a labeled position color or Borrar, then taps one-hour cells. The grid retains one row per imported shift, including separate split-shift rows. Any overlap of at least one minute makes an hour eligible. The current position is shown in the cell; a painted proposal is marked Pendiente. Deshacer reverses the last proposal, Descartar deliberately removes all proposals, and **Guardar cambios** is the only action that publishes them. Current or past erasures and moves require a move reason.

When all numbered rows are present, the palette shows one Nieves choice and one Trastes choice. These resolve to the first available numbered station in their explicit families (`nieves`/`nieves2` and `pdf_tsrea`/`pdf_tsr2`/`pdf_tsr3`/`pdf_tsr4`). An already valid number stays in place. A contiguous painted range prefers the same free number throughout; if none is free throughout, each hour takes its first free number. Concrete rows and other staged assignments count against capacity. The server allocates inside the save transaction, keeps the concrete numbered ID in the assignment and move log, and refuses a full family without publishing part of the draft. The manager sees the full-capacity message and can revise the proposal.

Pending changes are stored on the same browser device under the authenticated manager's ID, board, and date. They remain private after view/date/board changes, an idle or manual lock, network fallback, and reload. After unlocking, the manager can return to a date marked Borrador and review the proposals. Another manager does not inherit them through the UI. The app warns if device storage cannot retain or clear a draft and does not claim a failed retention succeeded. Drafts on one device do not roam to another device or survive cleared browser storage.

Before Guardar, the editor compares the imported shift ID, hours, employee, source position, and each touched assignment's ID and position with the values seen while painting. A changed shift or assignment keeps the draft for review and disables publication until conflicting proposals are deliberately removed or repainted. The server repeats these checks in one transaction, then validates station board, ability, occupancy, person/hour uniqueness, and move reasons. A failed save retains the draft. The save is all-or-nothing; staff never see staged cells.

The legacy one-hour, whole-shift, swap, clear, and back-office assignment paths remain available to managers. Server-side manager-session checks now protect assignment creation and swap as well as delete and paint. When I Work imports can change a shift's hours without changing its ID; the editor treats that as a conflict and requires review before saving.
